Waits:
------
	Definition:
		Waits in Selenium are used to synchronize the WebDriver with the application, ensuring that elements are loaded or visible before interaction, instead of failing immediately.
		
	Need:
		We need waits in automation testing because modern web applications are dynamic and elements may load due to AJAX calls, page refreshes, or delayed responses. Without waits, Selenium may try to interact with elements that are not yet available.
	Types:
		1. Implicit Wait
			Global wait applied to all elements
			WebDriver waits up to the specified time before throwing NoSuchElementException
			Defined once and applied throughout the driver session
			
		2. Explicit wait
			Applied to specific element Wiats for a  specific condition.
			Uses WebDriverWait with ExpectedConditions
				WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(20));
				wait.until(ExpectedConditions.visibilityOf(element));
			
		3. Fluent wait
			Similar to explicit wait with polling frequency and Exception ignoring
			
			
	Although Selenium allows using both waits together and it does not throw any exception, it is not recommended because implicit wait gets added to explicit wait internally, resulting in unpredictable and increased execution time.Hence, in real-time automation frameworks, we usually disable implicit wait and rely on explicit waits for better control.

ArrayList and LinkedList:
------------------------		

	Definition:
		ArrayList and LinkedList are implementation classes of the List interface used to store ordered and dynamic collections of elements.

	ArrayList:
		1. Internally uses resizable array
		2. Its access time is fast
		3. Insertion/Deletion is slow because elements need to be shifted.
		4. Uses a resizable array
		5. When capacity is full → creates a new array (approx 1.5x size) and copies elements
		6. It follows the insertion order and allows duplicates
		7. Allows to add null value 
		8. Consumes less memory compared to LinkedList.
	 

	LinkedList:
		1. Internally uses doubly linked list(node based)
		2. Its access time is slow 
		3. Insertion/Deletion is fast because node links can be updated without shifting elements.
		4. Uses nodes (each node has data + next + previous reference)
		5. No shifting required during insert/delete
		6. It follows the insertion order and allows duplicates
		7. Allows to add null value 
		8. Consumes more memory due to additional references.


	In my automation framework, I mostly use ArrayList because we frequently retrieve test data, WebElements, and API response values, while insertion and deletion operations are less common.
	
	
	When the ArrayList reaches its capacity and a new element is added, Java creates a new array with approximately 1.5 times the current capacity. All existing elements are copied to the new array, and the old array becomes eligible for garbage collection.

HashSet, LinkedHashSet and TreeSet:
-----------------------------------		

	Definition:
		HashSet, LinkedHashSet, and TreeSet are implementation classes of the Set interface used to store unique elements dynamically.

	HashSet:
		1. Does not allow duplicate values 
		2. Allow one null value
		3. Does not maintain insertion order 
		4. Internally uses HashMap.
		5. Provides best performance for add, remove, and search operations
	 

	LinkedHashSet:
		1. Does not allow duplicate values 
		2. Allow one null value
		3. Maintain insertion order 
		4. Internally uses LinkedHashMap.
		5. Slightly slower than HashSet due to maintaining order

	TreeSet:
		1. Does not allow duplicate values 
		2. Does not allow null values.
		3. Maintains natural sorting order 
		4. Internally uses Red-Black Tree (Tree Map).
		5. Slower than HashSet because sorting is maintained.

	In automation frameworks, I generally use HashSet for uniqueness checks, LinkedHashSet when insertion order is important, and TreeSet when sorted data is required.
	
	
HashSet Internally works:
-------------------------

	1. HashSet internally uses HashMap to store element.
	2. When we add an element into a HashSet, the element is stored as the Key in the underlying HashMap and a dummy constant object is stored as the Value.
	3. While adding element in HashSet , HashSet calls the  hashCode() method to generate an unique integer hashCode/hashvale and Based on the hash code, HashMap determines the bucket location.
	4. If the bucket is empty, the element is added.
	5. If another element already exists in the same bucket, HashSet calls the equals() method.
	6. If equals() returns true, the element is considered a duplicate and is not added.
	7. If equals() returns false, both elements can coexist in the same bucket.

	This combination of hashCode() and equals() helps HashSet maintain unique elements.

Map:
----
	Definition:
		Map is an interface in Java used to  stores the data in the form of key–value pairs, where each key is unique and maps to at most one value.
		Map is mainly used when data needs to be retrieved, updated, or searched using a key rather than by position.
		It is not a child interface of Collection, so it is not considered a true collection.
		


	Characteristics of Map:
		1. Stores data as key–value pairs
		2. Duplicate keys are not allowed
		3. Duplicate values are allowed
		4. Each key maps to only one value
		5. HashMap does not guarantee insertion order.
		6. LinkedHashMap maintains insertion order.
		7. TreeMap maintains sorted order based on keys.
		8. Provides fast retrieval using keys.

	Common implementations are:
		HashMap
		LinkedHashMap
		TreeMap
		
	In my Selenium automation framework, I use Map for storing test data such as Username → Admin and Password → Test123, and for storing API request/response data.	
		

	Map is an interface, and it has multiple implementations, each designed for different use cases.
		HashMap
			Does not allow duplicate keys.
			Allows duplicate values.
			Allows one null key.
			Does not maintain insertion order.
			Provides the best performance.
			HashMap internally uses a hash table to store data as key-value pairs.
		
			HashMap does not allow duplicate keys. If we insert the same key again, HashMap updates the value associated with that key and returns the old value (if captured).
		
		LinkedHashMap
			Does not allow duplicate keys.
			Allows duplicate values.
			Allows one null key.
			Maintains insertion order.
			Slightly slower than HashMap due to order maintenance.


		TreeMap
			Does not allow duplicate keys.
			Allows duplicate values.
			Does not allow null keys.
			Maintains natural sorted order based on keys.
			Slower than HashMap because sorting is maintained.
			
		Hashtable
			Synchronized (thread-safe)
			Does not allow null keys or null values
			Slower compared to HashMap
			Considered legacy				
			
		ConcurrentHashMap
			Thread-safe and highly performant
			Does not allow null keys or null values
			Uses internal locking for better concurrency
			Provides better performance than Hashtable in multi-threaded environments


	HashMap
	   ↓
	Hash Table

	LinkedHashMap
	   ↓
	Hash Table + Doubly Linked List

	TreeMap
	   ↓
	Red Black Tree

	Hashtable
	   ↓
	Hash Table + Synchronization

	ConcurrentHashMap
	   ↓
	Hash Table + CAS + Bucket Locking

String:
------
	Definition:
		String in Java 	is an object that represents sequence of characters, implemented using String class from java.lang package.
		Strings are immutable, meaning once created, their value cannot be changed. If any modification is performed, a new object is created instead of modifying the existing one.
		
	Memory allocation:
		String literals are stored in the String Constant Pool (SCP) inside the heap. If the same value already exists, JVM reuses the reference to optimize memory.
		
		String objects (new keyword) are always created in the heap memory, even if the value already exists.
			
			String s1 = "Test";
			String s2 = "Test";  // same reference from SCP
			String s3 = new String("Test"); // new object in heap
			
	Reason for immutability:
		Security (important for URLs, DB connections)
		Caching (String pool reuse)
		Thread safety (no synchronization required)

	Difference:

		2. String Buffer:

Frames:
-------
	Definition:
		Frames / iFrames are HTML elements that embed another web page inside a parent web page.
		Each frame has its own DOM, and Selenium can interact only with the currently focused DOM.
		Therefore, before interacting with elements inside a frame, we must switch Selenium’s control to that frame.
		
	Methods to access Frames:
		1, Switching frame Using index
			driver.switchTo().frame(0);
						
		2. Switching frame Using String (String may be Name or Attribute)
			driver.switchTo().frame("Name");
		
		3. Switching frame Using WebElement
			driver.switchTo().frame(frameElement);
			
	parentFrame() --> is used to switch control from the current frame to its immediate parent frame.

	defaultContent() --> is used to switch control back to the main page, i.e., outside all frames, regardless of the nesting level.
	
	Nested Frames:
		Nested frames are handled by switching sequentially from the main page to the parent frame and then to the child frame. Selenium does not support jumping directly to an inner frame. To exit, parentFrame() moves one level up, while defaultContent() returns to the main page.

API (Application Programming Interface):
---------------------------------------
	Definition:
		API is an set of rules and protocols that allows to  communicate from one application with another application.
		It works on request - response mechanism where one system sends request and another system returns response.
		
	Examples:
		When you use a mobile app to book a ticket, the app communicates with the server through APIs to fetch available tickets and confirm the booking.
		
	API Testing:
		API Testing is a type of testing where we validate the functionality, reliability, performance, and security of APIs without involving the UI.
		It involves sending requests to the API and verifying the responses such as status codes, response body, headers, and data correctness.
		
	API testing is important because:
		It helps identify defects early before the UI is developed.
		It is faster than UI testing.
		It is more stable since it is not affected by UI changes.
		It validates the communication between different systems.
		It improves overall software quality and reduces testing time.
		
	Real-time example: Instead of testing a login through UI, we directly send login API request and validate the response token.
	
	Types :
		1. Based on Access level
				Public API (Open APIs) --> Available for anyone to use (e.g., Google Maps API)
				Private API (Internal APIs) --> Used within an organization for internal communication
				Partner API --> Shared with specific business partners with controlled access
				Composite API --> Combine multiple APIs into a single request (used to improve performance)
		2. Based on Architecture level
				REST API --> Uses HTTP methods (GET, POST, PUT, DELETE), lightweight, widely used
				SOAP API --> Uses XML, more secure, follows strict protocol.
				
				
	API Request Components:
		An API request is sent by the client to the server to perform an action.
		It contains:
			HTTP Method (GET, POST, PUT, DELETE)
			URL (Endpoint) → identifies resource
			Headers → metadata (Authorization, Content-Type)
			Path Parameters → part of URL (/users/101)
			Query Parameters → filters (?status=active)
			Request Body → data sent (mainly in POST/PUT)
			Authentication → token, API key, etc.
		
		
	API Response Components:
		An API response is sent by the server back to the client after processing the request.
		It contains:
			Status Code → (200, 201, 400, 404, 500)
			Response Body → actual data (JSON/XML)
			Headers → metadata
			Response Message → success/error message	
			
		While testing an API response, I perform the following validations:
			Status Code Validation – Verify that the API returns the expected HTTP status code (200, 201, 400, 401, 404, 500, etc.).
			Response Body Validation – Validate the response data, mandatory fields, data types, values, null values, and business data.
			Response Header Validation – Verify headers such as Content-Type, Authorization, Cache-Control, and Server.
			Response Time Validation – Ensure the API responds within the expected time limit.
			Schema Validation – Check that the response structure matches the API contract or schema.
			Business Logic Validation – Verify that the API behaves according to the business rules.
			Database Validation (when applicable) – Ensure the API response matches the data stored in the database.	
					
	HTTPs status code are the  part of API response that indicate the result of the request sent by the client to the server
	It has different categories such as 
		1xx--> Request was received and the server is continuing the process.
		2xx--> Indicates the success reason 
				201 - Resource Created
				200 - Request was successful 
		3xx--> Indicates redirection	
		4xx--> Error on the client side
				400 - Bad request 
				401 - Unauthorized
				403 - forbidden
		5xx--> Error on the server side. 
				500 - Internal Error
				501 - Bad Gateway		
				
Rest Vs SOAP:
------------

	REST
		Representational State Transfer(REST) is a architectural style used to build webservices.
		Supports both JSON and XML
		It is  light weight and flexible
		Supports HTTP caching
		Easy to develop and consume
		Uses HTTP methods (GET, POST, PUT, DELETE, PATCH)
		Stateless (each request independent)	
		Widely used in modern web/mobile APIs

	SOAP
		Simple Object Access Protocol(SOAP) is a protocol used for exchanging structured information
		Supports  XML
		It is  heavy weight and follows strict standards
		Limited or No HTTP caching 
		Complex to develop and consume
		Uses XML messaging
		Can be stateful or stateless
		Used in banking and enterprise systems

HTTP Methods:
------------
	Definition:
		HTTP methods define the operations that can be performed on a resource in a REST API.
		
	Types:
		GET – Retrieves resource information.
		POST – Creates a new resource.
		PUT – Updates or replaces an existing resource completely.
		PATCH – Updates only specific fields of an existing resource.
		DELETE – Removes a resource.
		
	Idempotency:
		GET, PUT, and DELETE are idempotent.
		POST is not idempotent.
		PATCH is generally not guaranteed to be idempotent.

SQL Joins:
----------
	Definition:
		Joins is used to combine data from two more tables based on a related column.
	
	Types:
		1. Inner Join: 
					Returns only matching records from both tables.
						
							SELECT e.EmpId, e.Name, d.DeptName
							FROM Employee e
							INNER JOIN Department d
							ON e.DeptId = d.DeptId;						

		2. Left Join (or) Left Outer Join: 
					Returns all records from the left table and matching records from the right table.
					
						SELECT e.EmpId, e.Name, d.DeptName
						FROM Employee e
						LEFT JOIN Department d
						ON e.DeptId = d.DeptId;
						
		3. Right Join (or) Right Outer Join: 
					Returns all records from the Right table and matching records from the left table.
					
						SELECT e.EmpId, e.Name, d.DeptName
						FROM Employee e
						RIGHT JOIN Department d
						ON e.DeptId = d.DeptId;		

		4. Full Outer Join: 
					Returns matching rows plus non-matching rows from both tables.
					
						SELECT e.EmpId, e.Name, d.DeptName
						FROM Employee e
						FULL OUTER JOIN Department d
						ON e.DeptId = d.DeptId;		

		5. Inner Join: 
					Joining a table with itself.
					
						SELECT e.Name AS Employee,
							   m.Name AS Manager
						FROM Employee e
						LEFT JOIN Employee m
						ON e.ManagerId = m.EmpId;
						
		5. Cross Join: 
					Returns all possible combinations (Cartesian Product).
					
						SELECT *
						FROM Employee e
						CROSS JOIN Department d;				

Encapsulation:
--------------
	Definition:
		Encapsulatin is an OOP concept where data and methods are wrapped together into a single unit and internal data is hidden from outside access. It is mainly used to achieve data hiding by restricting direct access to the data.

	Uses:
		To achieve data hiding 
		To control how data is accessed or modified
		To improve security, maintainability, and flexibility.
		
	Internal working:
		Variables are declared as private
		Access is provided through public getter and setter methods
		We can also add validation logic inside setters to control incorrect data
		
	Real-time Project Example:
		In Selenium Page Object Model (POM), we declare WebElements as private and expose them via public methods (actions like click, sendKeys).
		This ensures:
			Elements are not directly accessed outside the class
			Changes in locators don’t affect test scripts
			Code becomes clean, reusable, and maintainable
			
			
	How Encapsulation Provides Data Security:
		Encapsulation ensures data security by restricting direct access to variables and allowing access only through controlled methods (getters & setters).
		This helps in:
			Preventing unauthorized modification
			Adding validation before updating data
			Controlling business rules centrally
			
	Real-world Scenario (Banking System):
		In a banking application, the account balance should not be modified directly.		
		User cannot directly change balance
		Only allowed operations (deposit/withdraw) are exposed
		Invalid operations are restricted using validation logic

Polymorphism:
------------
	Definition:
		Polymorphism means “one name, many forms”, where the same method behaves differently based on input parameters or object type.

	Types:
		1. Compile Time Polymorphism (Static Binding)
			Achieved using Method overloading
			Same method name with different method signatures:
				Different number of parameters
				Different data types
			JVM decides at compile which method to execute
		2. Run Time Polymorphism (Dynamic Binding)
			Achieved using Method overriding
			Child class provides specific implementation of parent class method
			JVM decides at runtime which method to execute
			
	In Selenium framework:
		We override methods like:
			setup() or teardown() in TestNG
		Different environments can have different implementations		
		Polymorphism in Selenium helps in writing flexible, reusable, and maintainable automation frameworks
			
	Difference	Method Overloading vs Method overriding
		Definition
			Same method name with different parameters
			Redefining parent class method in child class
		Class Level
			Same class
			Parent & Child class
		Parameters
			Must be different (type/number)
			Must be same
		Return Type
			Can change (but not alone)
			Must be same (or covariant)
		Binding
			Compile-time (Static)
			Runtime (Dynamic)
		JVM Decision
			At compile time
			At runtime
		Inheritance
			Not required
			Required
			
TestNG:
-------
	Definition:
		TestNG is an open source testing framework designed to make test automation more powerful & flexible.
		It is widely used with Selenium webDriver to organize, execute and managing the test cases.
		
	Compared to running Selenium scripts using a main() method, TestNG provides several advanced features such as:
		Annotations like @Test, @BeforeMethod, and @AfterMethod to manage test execution.
		Prioritization and dependency between test cases.
		Grouping of test cases.
		Parameterization using @Parameters and @DataProvider.
		Parallel execution for faster test runs.
		Built-in HTML reports.
	
	Annotations:
		Annotations are metadata provided to TestNG that define how and when test methods should be executed.
		They help organize the test lifecycle without writing manual method calls.
		Using annotations, we can perform setup, teardown, grouping, parameterization, and control the execution order of test methods.
		
		
								@BeforeSuite → Initialize reporting, global setup.
									↓
								@BeforeTest → Database connection, reading Excel/configuration.
									↓
								@BeforeClass → Initialize WebDriver or page objects.
									↓
								@BeforeMethod → Launch application, login, preconditions.
									↓
								@Test → Actual test execution.
									↓
								@AfterMethod → Logout, capture screenshots on failure, cleanup.
									↓
								@AfterClass → Close browser.
									↓
								@AfterTest → Close database connections or release resources.
									↓
								@AfterSuite → Flush reports, generate final report.
								@DataProvider → Execute the same test with multiple datasets.



Abstraction:

	Definition:
