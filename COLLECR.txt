Map:
----
	Definition:
		Map is an interface in Java used to  stores the data in the form of key–value pairs, where each key is unique and maps to at most one value.
		Map is mainly used when data needs to be retrieved, updated, or searched using a key rather than by position.
		It is not a child interface of Collection, so it is not considered a true collection.
		


	Characteristics of Map:
		1. Stores data as key–value pairs
		2. Duplicate keys are not allowed
		3. Duplicate values are allowed
		4. Each key maps to only one value
		5. HashMap does not guarantee insertion order.
		6. LinkedHashMap maintains insertion order.
		7. TreeMap maintains sorted order based on keys.
		8. Provides fast retrieval using keys.

	Common implementations are:
		HashMap
		LinkedHashMap
		TreeMap
		
	In my Selenium automation framework, I use Map for storing test data such as Username → Admin and Password → Test123, and for storing API request/response data.	
		

	Map is an interface, and it has multiple implementations, each designed for different use cases.
		HashMap
			Does not allow duplicate keys.
			Allows duplicate values.
			Allows one null key.
			Does not maintain insertion order.
			Provides the best performance.
			HashMap internally uses a hash table to store data as key-value pairs.
		
			HashMap does not allow duplicate keys. If we insert the same key again, HashMap updates the value associated with that key and returns the old value (if captured).
		
		LinkedHashMap
			Does not allow duplicate keys.
			Allows duplicate values.
			Allows one null key.
			Maintains insertion order.
			Slightly slower than HashMap due to order maintenance.


		TreeMap
			Does not allow duplicate keys.
			Allows duplicate values.
			Does not allow null keys.
			Maintains natural sorted order based on keys.
			Slower than HashMap because sorting is maintained.
			
		Hashtable
			Synchronized (thread-safe)
			Does not allow null keys or null values
			Slower compared to HashMap
			Considered legacy				
			
		ConcurrentHashMap
			Thread-safe and highly performant
			Does not allow null keys or null values
			Uses internal locking for better concurrency
			Provides better performance than Hashtable in multi-threaded environments
